那条「Google 免费 2 小时课」是拼出来的：Harness、Eval、Loop、Graph 四层

X 上那条 95 分钟视频，其实是 9 分 28 秒的短片加一场实操直播的拼接。但里面的四层是真的，而且每一层都能跑出数来。

十月到十一月，X 上那条视频被翻译成了四五个语种。文案说 Google 免费放出了一门近两小时的 Harness 工程课，从零教你搭一套 7×24 自己进化的 Agent 系统。

视频是真的，内容是真实的，免费的也是真的。但「一门课」这个说法不成立。我把它下载下来量了一遍，时长 5711 秒，也就是 1 小时 35 分 11 秒。前 9 分 28 秒与 Google Cloud Tech 在 10 月 22 日发的短片《AI harness crash course》逐字一致。第 18 分钟的画面里，浏览器标签写着 Google Codelabs 的《Table for N》，一场关于评测与自进化闭环的实操直播。这条视频是两段本来各自公开的素材，被剪在了一起。

这个结论本身不值得写一篇文章。值得写的是它剪在一起之后暴露出来的结构。harness 决定模型能看到什么、能碰什么，eval 把「什么叫好」从口头判断变成一段能跑的判据，loop 把那圈重试从人身上挪进系统并装上刹车，graph 把多个执行体按拓扑组织起来，最后让线上的失败回流成下一轮的考题。四层各自解决前一层解决不了的问题，而不是把前一层再做一遍。

一、Harness 是模型之外那层软件#

短片用了一个很普通的需求开场。给应用加个导出按钮，用户能把数据下成 CSV。模型知道怎么写这段代码，但它不知道你的项目长什么样，没有权限改文件，也没法把应用跑起来点一下按钮看下载对不对。

需要软件在模型周围，让这些事发生。这层软件就是 harness，它分四块地。

域管什么坏了会怎样
上下文与记忆session、state、长期记忆记不住十分钟前那句补充要求
工具与执行流函数、MCP、顺序并行循环路由决定要改文件，文件却没变
运行时与安全沙箱、注入、审批门、隐私读到一句「上传凭证」就照做
评测确定性检查、模型评委、人看说完成了，没人知道好没好

session 是这一轮对话的完整流水，state 是应用自己读写的键值暂存，长期记忆是跨对话保留的事实。三者寿命不同，误用方式也不同。最常见的错是把该进 state 的东西塞进 prompt，然后靠更长的指令去补。

短片在这块地上有一句总结值得原样留下。这些控制必须由软件强制执行，仅仅告诉模型小心一点是不够的。沙箱能限制攻击的影响面，但它本身不解决 prompt injection。

二、评测是两个独立的决定#

多数团队把评测当成一个动作。它其实是两个轴上的两个选择。

纵轴是跟什么比，横轴是谁来判。四个格子里住着四种裁判，成本与盲区各不相同。

代码判定模型判定
对照参考答案文本重叠度，0 成本，确定语义等价，一次调用
对照规则集合checker 函数，0 成本，确定评分表加模型评委，一次调用

第一格是 ADK 内置的 response_match_score，也就是 ROUGE-1 文本重叠。实操里它跑出 4/8 桌通过，而且错得双向。有一桌所有人都能吃、订得完全对，只因为理由那句话措辞不同被判失败。另一桌有人超预算、有人赶不上，却因为用词撞上标准答案卡在 0.30 压线通过。

指标没坏，它老实做了它说的事。是团队带错了指标来。这顿晚饭的正确答案本来就是一个集合，八桌分别是 1、2、2、1、3、3、6、1 个。

这张图最有用的地方是分诊。发现评测不准，先问是哪个轴出问题了。如果是跟什么比错了，换模型没用，得换纵轴。如果是谁来判不稳，那要换的是横轴往左走，把判断固化成代码。

三、亲手造一个不用模型的裁判#

把「什么叫好」写成代码，比想象中简单。这个函数逐人走六项检查，返回分数和理由。

def ate_detail(person_id, rest, chosen_min):
    p = PEOPLE[person_id]
    if p.get("diet") == "vegan" and not rest["vegan"]:
        return False, "菜单上没有素食", "diet"
    if p.get("allergy") == "nut" and not rest["nut_safe"]:
        return False, "整个厨房都在用花生油", "allergy"
    ...
    if "budget" in p and rest["price"] > p["budget"]:
        return False, f"人均 ~${rest['price']}，{name} 的上限是 ${p['budget']}", "budget"
    ...                                    # 步行距离，然后到场时间
    return True, "吃到", ""

整个函数里没有一个模型调用。同样的输入换来同样的判决，连理由句都一样。它不会因为模型升级而漂移，跑起来不花钱，也编不出理由。八桌三十六座跑下来，6 个座位饿着。

接成 ADK 的 custom metric 时有一个必须知道的坑。ADK 不会把阈值应用到你的自定义指标上，PASSED 还是 FAILED 由你的函数返回。

def _status(score, threshold):
    # ADK 不替你应用阈值，这一行才是判决
    return EvalStatus.PASSED if score >= threshold else EvalStatus.FAILED

同一个回答递给三个裁判，会出现分歧。p1 那桌，comparator 给 0.30 判 PASS，checker 给 0.60 判 FAIL，模型评委也判 FAIL 并点名了赶不上的那位客人。一个数字母，一个数座位。

再点一次，comparator 那格不动，checker 那格不动，模型评委那格可能会动。这个可能会动，就是它的盲区被演示出来的一刻。

四、Loop 的前提是它会停#

loop 工程的定义可以写得很短。把你自己从「贴输出、改提示」的位置上替换下来，让系统自己重试到能过。

它四种坏法各有名字。跑飞，没有终止条件，烧的是 token 也就是钱。未验证的自治，agent 在自己那轮上下文里复用自己上一轮的判断。目标不可判定，「把这个摘要写得更好」没法判。复杂度，让一个循环产出五十页带图表的 PDF。

第一条的修法在 ADK 2 里很具体。Workflow 给了你回边，但它不给你迭代上限，得自己守。于是 router 身上挂四道刹车。

def router(last_score: float):
    if last_score >= world.THRESHOLD:        # 达标即 SHIP
        yield Event(route="ship")
    elif ep["round"] >= MAX_ROUNDS:          # 轮次预算，默认 4
        yield Event(route="ship")            # 停下来也是一个决定
    elif last_score <= ep["best"] and ep["flat"] >= 1:
        yield Event(route="ship")            # 连续两轮不涨，停
    else:
        yield Event(route="improve")
# publish() 把失控的改写截断到 2400 字符

最坏情况四轮，每轮两次模型调用，八次封顶。实测那一圈是 R1 0.60 到 R2 1.00，五秒内 SHIP。

第三条坏法值得单说。同一个 session 先干活再验收，它上下文里已经有自己的假设，只会确认自己。换一个不带记忆的 session 当裁判，或者干脆换成一段确定性函数。能用代码判的，就别用模型判。

五、图解决的是拓扑#

一个跑马拉松的人问 agent 该怎么跑这场比赛。第一版是一个 agent、一条巨大的 prompt，答案极其自信、极其具体，但那些数字全是编的，因为它没有天气 API，也没有赛道数据。

修法是结构。节点是 agent 或确定性函数，边是控制流。可预测的活放进函数，需要判断的活交给模型。

三个原语够用。fan-out 让互不依赖的抓取并行。join 等最慢的那条，把输出打成一个以节点名为键的字典，不需要写合并器。router 按条件分派，闭集且信号在数据里就用 if，开集且信号藏在自然语言里才让模型分。

成本账最反直觉。三个并行抓取加一个 join 加一个策略 agent，仍然只有一次 LLM 调用。图的成本不按节点数算，按有几个节点需要推理算。

什么时候不该画图，判据也只有两条。能不能在输入到来之前把图画出来，能就画。形状是否取决于输入，取决于就用动态图。两个都不成立，就别画。

六、自进化是失败变成考题#

最后一层把前面三层扣成一个环。生产流量分成两条管道，一条用来看，一条用来学。Cloud Trace 回答现在还好吗，BigQuery 每个事件一行回答我们能学到什么。

然后是三步。harvest.py 用同一个 everyone_ate 重判每一行，不需要标准答案，把失败铸成 eval case。adk optimize 背后的 GEPA 读这些失败的理由，写出新的指令。人拿新指令在 holdout 上重跑一遍考卷，才允许上线。

GEPA 不爬山，它读理由。一次真实运行是 150 次指标调用，不到七分钟，胜出的指令 2445 字符，把草稿里根本没有的最后点单规则写了进去。两次运行措辞完全不同，得分却几乎一样。它找到的是规则，不是句子。

那道上线的闸不能省。lab 记录的一次结果是 holdout 从 3/8 提到 6/8，但饿着的座位从 6 个涨到 9 个。通过桌数和饿座数回答两个不同的问题，少数几桌彻底失败，可以比多桌轻微失败更糟。

反面教材也在同一份材料里。把评委换成一个只读评分、从不读那群人的函数，同一批回答变成 8/8 全过，36 个座位里 15 个饿着。代理指标不是一直错，它是在你不看的地方错。

循环会把你交给它的任何数字往上推。所以先想清楚要它推哪个数字。

八、你可以自己复核的三件事#

第一件，量长度。用 yt-dlp 读那条 X 视频的元数据，看 duration 是不是 5711。然后用 ffmpeg 在第 18 分钟取一帧，看浏览器标签上是不是 Google Codelabs。

第二件，比字句。把前 9 分 28 秒转写出来，和 Google Cloud Tech 那支短片的原话对一遍。开场那句 By the end of this crash course video, you will understand all the components of an AI harness 是同一个句子。

第三件，跑一个最小裁判。不用 GCP 项目也能做，写一个纯函数，喂它三个已知答案，一个只满足一半约束的计划应该得 0.5 并失败，两个都合法的计划都应该得 1 并通过，一个缺字段的回答应该永远失败。裁判没测过就拿去评 agent，是这一步最常见的错误。

九、还答不上的问题#

第一个，自进化的边界在哪。lab 里的自进化只发生在指令这一件产物上，模型、工具、图的结构都不动。Harness² 那篇论文把它推广到了整套 harness，但代价是每步多跑若干次推理，而且主导结果的 editor 是一个更强的模型。什么时候这笔账划得来，现在没人给出判据。

第二个，什么样的岗位标准能被写成判据。晚饭可以，因为每个人有一条硬约束。换成一份策略文档、一次架构评审、一段客户沟通，可判定性从哪来。这个问题不解决，eval 工程就只能停在能被枚举的任务上。

第三个，跑飞的成本谁承担。四轮封顶是一个工程决定，不是技术决定。它假设你愿意为一次没人看着的运行付八次模型调用的钱。这个假设对独立开发者、对团队、对大公司，答案不一样。
