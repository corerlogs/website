Harness 是新的操作系统

同一份权重换八种 harness，分数差 8.7。把上下文、接口、执行、反馈四件事拆开，看看这一层到底做了什么。

模型给的是能力，harness 决定这份能力能变成什么。

一、先看一组数#

DeepSeek-V4.1-Flash 是同一份权重。把它塞进八种 harness 跑 DeepSWE v1.1，最高的 mini-SWE-agent 拿到 74.2，最低的 OpenCode 拿到 65.5。八点七分的差距，落在同一个模型名下。

对照组在另一头。同一个模型，只换 Claude Code 的版本号，四个版本之间差 1.1 分和 1.4 分。

两句话放在一起，harness 就是一个能改变结果的变量。2026 年 11 月 QCon 旧金山的开场演讲里，Mad Labs 创始人 Manju Rajashekhar 把它摆在操作系统的位置，讲题就叫《The Harness Is the New Operating System》。

二、这块牌子别人挂过#

应用程序写行为，操作系统抽象硬件。这两件事分开之后，软件才能搬走、才能组合。agent 把这个安排顶开了，因为它在运行时生成行为，没人替它收着。

Rajashekhar 的定义很省事，模型加 harness 等于 agent，harness 是 agent 里不是模型的那部分。它负责任务、上下文、工具、状态、权限、反馈回路，还有一个「做完」的定义。

最小的 agent 就是模型跑在一个循环里，循环由 harness 控制。循环不够，每一轮都得算数。

三、四个位置，写成要件#

第一件是上下文，位置对应虚拟内存。窗口有硬上限，harness 决定这一轮往里面放什么。他的说法是给模型一个指针，别把整堆东西倒进去。

第二件是接口，位置对应系统调用。接口给 agent 的能力封顶，SWE-agent 那篇论文里，同一个 GPT-4 Turbo 在 SWE-bench Lite 上从 11.0% 走到 18.0%，差别只在工具接口为 agent 重画过。

第三件是执行，位置对应进程与权限。隔离和作用域凭据在这里干活，比如给 agent 一个没有生产权限的测试库。一句话拦不住的东西，边界拦得住。

第四件是反馈，位置对应返回码。测试没过、跑不起来、结果未知，三件事必须分开报。合成一句「失败」，模型只能猜，猜错一次，后面几轮都顺着错下去。

四、算术比口号硬#

错误会滚雪球这件事可以直接算。二十步的任务，每步九成半把握，二十步全对的概率是 0.95 的 20 次方，等于 0.358。

把八成的错误当场抓住，每步变成 0.99，0.99 的 20 次方是 0.818。

二十步只是举例子。任务拉到五十步，0.95 掉到 0.077，0.99 还有 0.605。步骤越长，harness 的反馈通道越值钱。

五、权威不是能力#

修好一个挂掉的测试，和一个删掉测试让它变绿的 agent，差别不在能力，在权限。这句话演讲里说得干脆，指令只能引导，边界才能强制。

2026 年 7 月的事故把这句话演了一遍。OpenAI 的评测环境里，几个 agent 顺着包缓存代理摸到外网，进了 Hugging Face 的集群，拿着管理员权限待了大约两天半。它们的动机写在事后报告里，把评分器改过去，让不可能的任务通过。

评测对象能改写反馈通道，那它就不再是边界。同一个道理落在审批上。Anthropic 公布过两个数字，Claude Code 用户批准权限提示的比例是 93%，八月那篇公告写的是 97%。人看多了会麻木，一个累了的守门人就是橡皮图章。同一批测试里，自动模式在 1,053 名付费测试者身上拦住 89% 的危险动作，人工审核拦下 13.6%。

六、换 harness 不换模型#

agent 绕圈子的时候，多数人的第一反应是换模型。换这一层往往更便宜。

DeepSeek 那组八种 harness 的极差是 8.7 分。Qwen3.8-27B 那组更陡，单次调用在 LiveCodeBench 难题上过 66.8%，加上管理者、工人和一份共享账本，到 92.4%，涨了 25.6 个百分点。LangChain 只动 harness，把模型反复跳过的自检挪进循环，Terminal-Bench 2.0 从 52.8% 到 66.5%。

数字好看，前提也得写清楚。Qwen 那组是五次尝试取的结果，题目里 27 道没有公开测试可跑，只有隐藏测试判分。DeepSeek 那组里，极简 harness 拿了最高分，但外部的 Claude Code 69.8 高过自家的 DSH PTC 67.6，所以「越少越好」不成立，对得上的那一版才成立。

八、你自己能做的三件事#

打开你已经在用的 agent，读两样东西。system prompt 里写着它被要求怎么做，工具表里写着它实际能碰什么。两样经常对不上，对不上的地方就是边界漏风的地方。

再把失败分三栏记账。测试没过写一栏，跑不起来写一栏，结果未知写一栏。一周之后哪一栏最厚，你要修的就是那一栏对应的 harness 零件，不是模型。

最后挑一个它做不好的任务，只改循环里的一处，重跑同一批任务。改之前记下通过数，改之后记一次。一次只改一处，改两处你就不知道该谢谁。

九、还没答上来的#

harness 之间有没有可比的接口。现在同一份权重换一层壳，分数就换一个含义，排行榜上那串数字说的到底是模型还是壳，报告里很少写清楚。

还有一条更远。当模型开始自己写 harness、自己决定什么时候重置上下文，边界该归谁定。现在的答案是外面的工程师，这个答案能撑多久，我不知道。
